# 第三阶段：Prompt 与 Context Engineering——给智能体"装好上下文"

> 2026 年，Prompt Engineering 已经进化为 **Context Engineering**——不只是写好提示词，而是系统性地将正确的信息在正确的时机传递给智能体。

## Context Engineering 是什么

Context Engineering（上下文工程）是 Agentic AI 的核心技能。它关注的是：

> **如何构建、路由、选择性加载上下文，让智能体在正确的时间获得正确的信息和能力。**

### 为什么重要

- 模型能力越来越强，但**上下文管理**成为瓶颈
- 好的上下文 = 好的 API 设计
- [Agentic Context Engineering (ACE)](https://openreview.net/forum?id=eC4ygDs02R) 框架将上下文视为"可演进的 playbook"

## 上下文的 5 个层次

```
层次 5 ─→ 元上下文（自我改进、经验积累）
              ↑
层次 4 ─→ 社会上下文（多智能体共享、协作记忆）
              ↑
层次 3 ─→ 程序上下文（工具定义、工作流状态）
              ↑
层次 2 ─→ 知识上下文（RAG 检索、文档分块）
              ↑
层次 1 ─→ 对话上下文（系统提示、用户指令）
```

## 层次 1：系统提示设计

### 好的提示 = 好的 API 接口

```python
# 差的提示——模糊、不可测试
prompt = "你是一个助手，帮我回答问题"

# 好的提示——明确、结构化、可测试
SYSTEM_PROMPT = """你是一个知识库问答助手。

## 角色
- 根据用户的问题，从检索到的知识片段中提取答案
- 只回答与知识相关的问题，不要编造

## 约束
- 如果知识中没有答案，回复"抱歉，我目前没有相关信息"
- 必须引用具体的知识来源
- 不要使用知识之外的信息

## 工具使用策略
- 当用户询问具体事实时，先调用搜索工具
- 当用户要求执行操作时，先确认再执行
- 当工具返回错误时，不要重试超过 2 次

## 输出格式
回答应包含：
1. 直接答案（1-2 句话）
2. 来源引用（引用知识片段的编号）
"""
```

## 层次 3：程序上下文

### 工具定义

将工具的 Schema 作为上下文的一部分：

```python
# 工具定义——LLM 能理解的结构化描述
tools_context = """
可用工具：
1. search_knowledge(query: str, limit: int) -> list[Result]
   - 搜索内部知识库
   - 适用：查找公司政策、产品信息
   - 不适用：实时新闻、天气

2. send_email(to: str, subject: str, body: str) -> bool
   - 发送邮件
   - 有副作用——需要用户确认
   - 适用：发送通知、报告

3. get_current_time() -> str
   - 获取当前日期时间
   - 无参数
"""
```

### 工作流状态

```python
# 将当前执行状态作为上下文
state_context = """
当前任务状态：
- 用户请求：分析 Q3 财报
- 已完成步骤：[1. 搜索财报文档, 2. 提取关键数据]
- 当前步骤：3. 生成分析报告
- 已收集数据：营收 120 亿，利润 15 亿
"""
```

## 层次 4：社会上下文（多智能体）

在多智能体场景中，需要传递：
- 其他 Agent 的角色和能力
- 协作协议（谁负责什么）
- 共享工作区（共享记忆）

## 层次 5：元上下文（自我改进）

这是 Context Engineering 的最高层次——让 Agent 从经验中学习。

```python
# 经验积累——记录成功和失败的案例
experience_context = """
过往经验：
- 成功：搜索技术文档时，使用"产品名 + 版本号"作为关键词效果最佳
- 失败：上次用户要求发送邮件时未确认就执行，导致发送了错误内容
  修复：现在发送有副作用操作前必须先确认
"""
```

## Prompt 版本化管理

```
prompts/
├── v1/
│   ├── qa_prompt.txt       # 初版：简单问答
│   └── tool_prompt.txt
├── v2/
│   ├── qa_prompt.txt       # 优化了引用格式
│   └── tool_prompt.txt     # 添加了重试逻辑
└── v3/
    ├── qa_prompt.txt       # 添加了多轮对话支持
    └── tool_prompt.txt     # 优化了工具描述
```

像代码一样管理提示版本，确保每次调用的稳定性。

## 阶段实战

**目标**：为同一个任务编写 3 个版本的提示词，逐步优化

- [ ] v1：简单问答提示
- [ ] v2：添加角色、约束、输出格式
- [ ] v3：添加工具策略和错误处理
- [ ] 对比 3 个版本的效果差异

## 阶段检查清单

- [ ] 理解 Context Engineering 的概念和 5 个层次
- [ ] 能编写结构化系统提示
- [ ] 能将工具定义、工作流状态作为上下文
- [ ] 了解元上下文的概念，知道如何让 Agent 积累经验
- [ ] 能像代码一样版本化管理提示
