# 学习检查清单与面试锦囊

> 为了帮助大家高效学习、快速备战面试，整理了路线图核心的 10 步学习清单，可对照清单逐一突破，避免遗漏重点。

## 10 步学习检查清单

### 1. Python 根基

- [ ] 熟练掌握类型注解
- [ ] 能开发 REST API（FastAPI）
- [ ] 理解异步编程（async/await）
- [ ] 能编写单元测试

### 2. LLM 通识

- [ ] 吃透 Token 机制
- [ ] 能管理上下文预算
- [ ] 掌握提示工程（角色、约束、输出格式）

- [ ] 从简单的 LangChain 用法入手
- [ ] 掌握 LangGraph 图式工作流

### 4. 高阶工程

- [ ] 掌握组件组合（LCEL）
- [ ] 实现重试机制
- [ ] 实现降级策略
- [ ] 掌握参数校验

### 5. 记忆体系

- [ ] 实现摘要记忆

### 6. 工具工程

- [ ] 熟练设计结构化工具

### 7. RAG 实战

- [ ] 实现评估流程

### 8. 智能体协作

- [ ] 理解 ReAct 模式

### 9. 全栈项目

### 10. 面试锦囊

## 面试核心策略

### 带 2-3 个亲手开发的小型实战项目

> 面试时，无需追求"高大上"的项目，带上 2-3 个你亲手开发的小型实战项目（哪怕是简单的 RAG 聊天机器人、小型工具调用 Agent）。

推荐项目组合：

| 项目 | 展示能力 | 复杂度 |
|------|----------|--------|
| RAG 聊天机器人 | RAG 全流程 + LLM 调用 | ★★ |
| 工具调用 Agent | Function Calling + 工具设计 | ★★★ |
| 带记忆的 Agent | 三层记忆 + LangGraph | ★★★★ |
| 生产级 Agent 服务 | FastAPI + Docker + 可观测性 | ★★★★★ |

### 重点准备一个失败案例

> 重点准备一个你亲手调试过的失败案例——比如检索噪音过大、工具调用超时、Schema 解析异常等，清晰说明你是如何分析问题、定位原因、最终修复问题的。

**STAR 法则**：

- **S**ituation（情境）：描述问题的背景
- **T**ask（任务）：你要解决什么问题
- **A**ction（行动）：你做了什么来解决
- **R**esult（结果）：结果如何，学到了什么

### 示例回答模板

```
问题："请分享一个你在 Agent 开发中遇到的最大挑战。"

回答框架：
S - 背景：
  我在开发一个知识库问答 Agent 时，用户反馈模型经常给出不准确的答案。

T - 任务：
  我需要定位是检索问题还是模型幻觉。

A - 行动：
  1. 首先检查了检索结果——发现 BM25 和向量检索返回的文档相关度差异很大
  2. 分析了 chunk_size——当时设为 1500 Token，太大导致每个块包含多个主题
  3. 调整为 500 Token + 75 overlap 重叠，并引入 CrossEncoder 重排序
  4. 在提示词中增加了"仅基于以下知识回答"的约束

R - 结果：
  准确率从 65% 提升到 89%。
  我学到了：检索质量是 RAG 系统的生命线，分块策略需要通过评估来调优，
  而不是凭直觉。
```

## 面试高频考点

### 技术考点

| 考点 | 常见问题 | 准备方向 |
|------|----------|----------|
| Token 机制 | "如何管理长对话的上下文？" | 截断、摘要、压缩 |
| 工具调用 | "如何防止模型调用错误的工具？" | Schema 验证、路由逻辑 |
| RAG | "如何提高检索准确率？" | 混合检索、重排序、分块优化 |
| 记忆管理 | "如何实现跨会话记忆？" | 向量库存储、检查点 |
| 多智能体 | "什么时候该用多智能体？" | 任务复杂度分析、过度设计避免 |
| 生产部署 | "如何保证 Agent 服务的稳定性？" | 容器化、监控、重试、降级 |

### 工程素养考点

| 考点 | 常见问题 | 准备方向 |
|------|----------|----------|
| 调试能力 | "怎么排查一个偶发的 Agent 错误？" | Trace ID、日志、复现步骤 |
| 安全 | "如何防止 Prompt 注入攻击？" | 输入验证、输出过滤、权限控制 |
| 成本 | "如何降低 Agent 运行的 Token 成本？" | 上下文优化、模型分级、缓存 |
| 评估 | "如何评估一个 Agent 的好坏？" | 自建测试集、指标定义、A/B 测试 |

## 区分"熟练工"与"工程师"的关键

> 这种解决真实工程问题的能力，正是区分"熟练工"与"工程师"的关键，也是面试官最想看到的核心竞争力。

| 熟练工 | 工程师 |
|--------|--------|
| 会套用框架的 Demo | 能设计自己的架构 |
| 知道怎么用 | 知道为什么这么用 |
| 出了问题不知道怎么办 | 能系统性定位和修复 |
| 复制粘贴代码 | 封装接口、抽象层 |
| 只关注功能 | 关注可观测性、安全、成本 |

## 最后提醒

> Agentic AI 工程是一个"实战为王"的领域，小白和程序员切勿只看不动手，按照这份路线图，循序渐进夯实基础、完成实战项目，2026 年就能顺利入门 Agentic AI 领域，抓住行业新风口。

### 学习节奏建议

| 阶段 | 建议节奏 |
|------|----------|
| 第一、二阶段（基础） | 每天 2 小时，1-2 周完成 |
| 第三、四阶段（框架） | 每天 2 小时，4-6 周完成 |
| 第五、六阶段（实战） | 每天 2-3 小时，5-7 周完成 |
| 面试准备 | 持续进行，每个阶段完成后回顾 |
